## 4. 数据库设计

### users
| 列 | 类型 | 说明 |
|----|------|------|
| id | str PK | `U` + 雪花/时间戳，与前端 `UserAccount.id` 同形 |
| username | str unique | 11 位手机号（注册校验同前端：`^\d{11}$`、密码 6–20） |
| password_hash | str | bcrypt |
| avatar | str default '' | 暂不传图，留列 |
| created_at | datetime | 响应时转 ISO 字符串 → `createdAt` |

### stations
`id(str PK) name address lat(float, 纬度) lng(float, 经度) distance_km(float, 无定位时回退展示值) price_per_kwh business_hours created_at`
—— 前端 `ChargingStation` 一一对应；`free_piles` 不入库，由 piles 聚合计算返回。`lat/lng` 为地图定位与距离计算依据；`distanceKm` 有定位时由服务端按坐标实时计算（§10 决策 2）。

### piles
`id(str PK) station_id(FK) code(unique 二维码内容) lat float lng float power_kw price_per_kwh interface_type status(IDLE|CHARGING|OFFLINE|FAULT)`
—— 桩状态**以库为准**（解决前端「订单持久化但桩状态内存翻转重启复位」的技术债）。每个桩独立 `lat/lng` 用于地图点位标注（与前端 map.html 逐桩打点一致）。
展示元数据（slotCode/floor/ground）后端先不建模（第 10 节决策项），前端继续用本地 DisplayMeta。
`FAULT` 语义：桩故障，启动充电与费用预估一律拒绝（409）；仅经 `services/charging.py` 规则路径或运维改状态，不在 seed 之外由设备直改。

### refresh_tokens
`token(str PK, 随机串) user_id(FK) expires_at revoked(bool 默认false) created_at`
—— 支持 `POST /auth/refresh` 轮换（旧 token 置 revoked 后发新）与 `POST /auth/logout` 撤销；用于 access 过期后静默续期，避免反复登录。

### charging_orders
`id(str PK CO+ts+rand) user_id(FK) station_id station_name pile_code start_time end_time(null=进行中) energy_kwh unit_price duration_min amount status(CHARGING|FINISHED)`
—— `unit_price` 下单时快照桩单价；`amount = round(energy × unit_price, 2)` 结算时算。
—— `station_name/pile_code` 冗余存储（订单是历史凭证，不随站点改名漂移），与前端模型一致。

**不变式**（实现与测试都必须覆盖）：
1. 一个用户至多 1 个 CHARGING 订单（对应前端「已有进行中的充电订单」拦截）。
2. 订单关联桩在 CHARGING 期间 status 必为 CHARGING；结算/终止后回 IDLE。
3. FINISHED 订单字段不可变。

### user_settings（自动断电偏好，Story 11）
`user_id(str PK/FK→users) auto_stop(bool) stop_energy_kwh(float, 达到该电量自动停止) stop_threshold(float, 百分比阈值,预留给「车辆电量」来源)`
—— 一行一用户，懒创建（GET 无记录时返回默认值不落库）；`stop_threshold` 为偏好留存字段，实际按电量阈值触发自动断电（见 §7.1）。

### daily_charging_stats（每日充电统计，Story 12）
`id(str PK DS+ts+rand) user_id(FK) date(str YYYY-MM-DD) total_energy_kwh(float) total_amount(float) order_count(int)`
—— 每次结算（stop）后按 `user_id + date` upsert 累加；`date` 按端上当日 UTC naive 日期定型。

### vehicles（C 域 · Story 4）
`id(str PK V+ts+rand) user_id(FK unique) plate_no(str,默认"") battery(int,默认75) range_km(int,默认260) updated_at`
—— 每用户至多一辆默认车辆；`GET /vehicle/current` 无记录时落一条默认值再返回（§5.7）。展示端「爱车」属超纲页，接口先备、入口未开。

## 5. API 设计（v1）

通用：`/api/v1` 前缀；除 auth 注册/登录外全部 `Authorization: Bearer <token>`；
错误用 HTTP 状态码 + FastAPI 默认 `{"detail": "..."}`，**前端 HTTP 层负责映射回
`{success, message}` DTO**（映射规则写死在前端 service，本文档不重复）。
时间一律 ISO8601 字符串。

### 5.1 auth
| 方法 | 路径 | 请求 | 成功响应 |
|---|---|---|---|
| POST | `/auth/register` | `{username, password}` | 201 `{token, refreshToken, user: UserOut}` |
| POST | `/auth/login` | `{username, password}` | 200 `{token, refreshToken, user: UserOut}` |
| POST | `/auth/refresh` | `{refreshToken}` | 200 `{token, refreshToken, user: UserOut}`（轮换，旧刷新令牌作废） |
| POST | `/auth/logout` | `{refreshToken}`(可省) | 200 `{detail: "ok"}`（撤销刷新令牌；不传则撤销该用户全部） |
| GET | `/auth/me` | — | 200 `UserOut` |

`UserOut = {id, username, avatar, createdAt}`（**永不回传密码字段**）。
401=账号/密码错误或被撤销；409=用户名已存在。前端 `rememberPassword` 保持纯本地行为，与后端无关。

### 5.1.1 user/profile（A 域 · Story 16）
| GET `/user/profile` | — | 200 `Envelope<UserOut>`（当前登录用户，不可串号） |
| PUT `/user/profile` | `{avatar}` | 200 `Envelope<UserOut>` |

`username` 为登录凭证（11 位手机号、全局唯一）——**不可修改**；`PUT` 仅允许更新 `avatar` 等展示字段。

`username` 为登录凭证（11 位手机号、全局唯一）——**不可修改**；`PUT` 仅允许更新 `avatar` 等展示字段。

### 5.2 stations
| GET `/stations` | 200 `StationOut[]`（含嵌套 piles） |
| GET `/stations?lat=&lng=&radius=` | 200 `StationOut[]`：服务端 haversine 按 `lat/lng` 计算每站 `distanceKm`，`radius`(km) 为空则不过滤，非空则仅保留距离 ≤ radius 的站，结果按距离升序 |
| GET `/stations/{id}` | 200 `StationOut`；404 桩站不存在 |
| GET `/piles/{id}` | 200 `PileOut` |
| GET `/piles/by-code/{code}` | 200 `PileOut`（扫码解析入口） |

`PileOut = {id, stationId, code, latitude, longitude, powerKw, pricePerKwh, interfaceType, status}`（`status` 含 `FAULT`，前端 `Types.ets: PileStatus` 需同步）
`StationOut = {id, name, address, latitude, longitude, distanceKm, freePiles, pricePerKwh, businessHours, piles[]}`
`distanceKm`：带 `lat/lng` 查询时取 haversine 计算值；未带时回退入库 `distance_km`。

### 5.3 charging（会话 = 订单的生命周期）
| POST `/charging/start` | `{pileId}` → 201 `OrderOut`(status=CHARGING)；409=桩不可用（含 FAULT）/已有进行中订单 |
| GET `/charging/current` | 200 `RealtimeOut`（当前用户进行中订单的实时数据）；404=无进行中会话 |
| POST `/charging/{order_id}/stop` | → 200 `OrderOut`(FINISHED 结算后)；404/409=订单不属于当前用户或已结束 |
| POST `/charging/estimate` | `{pileId, expectedMinutes}` → 200 `EstimateOut`；404=桩不存在，409=桩不可用（含 FAULT） |

`RealtimeOut = {voltage, current, powerKw, durationSec, energyKwh, estimatedCost}`（数值，前端自行格式化）
`EstimateRequest = {pileId, expectedMinutes}`（正整数分钟）；`EstimateOut = {pileId, unitPrice, powerKw, expectedEnergyKwh, estimatedCost}`
—— 预估口径：`expectedEnergyKwh = round(powerKw × expectedMinutes / 60, 2)`，`estimatedCost = round(expectedEnergyKwh × unitPrice, 2)`，仅供参考，最终以 stop 结算为准。

### 5.4 orders
| GET `/orders?page=1&size=10&status=FINISHED` | 200 `Envelope<OrderPage>`（分页+状态过滤，新单在前，仅本人） |
| GET `/orders/{id}` | 200 `OrderOut`；404 |

`OrderOut = {id, stationId, stationName, pileCode, startTime, endTime, energyKwh, unitPrice, durationMin, amount, status}`
（`endTime` 进行中返回 `""`，与前端约定一致）
`OrderPage = {items: OrderOut[], page, size, total}`；`size` 默认 10、上限 50；`status` 可空。

### 5.5 D 域 · 扫码/偏好/统计（Story 9/11/12，新接口一律走 §5.5 统一响应）
| POST `/scan/resolve` | `{code}` → 200 `Envelope<PileOut>`；桩不存在/不可用 → 404/409 |
| GET `/user/settings` | — → 200 `Envelope<UserSettingsOut>` |
| PUT `/user/settings` | `{autoStop?, stopEnergyKwh?, stopThreshold?}` → 200 `Envelope<UserSettingsOut>` |
| GET `/stats/daily?days=7` | — → 200 `Envelope<DailyStatsOut[]>`（零填充近 N 天，含当日当天累计） |

`UserSettingsOut = {autoStop, stopEnergyKwh, stopThreshold}`；`DailyStatsOut = {date, totalEnergyKwh, totalAmount, orderCount}`；
`Envelope<T> = {success, errorCode, message, data}`（见 §5.6）。

### 5.6 统一响应（D1 约定）
新建 `schemas/common.py` 的 `Envelope[T]` 基类：成功 `{success: true, errorCode: 0, message: "ok", data: <T>}`，
错误仍走全局异常处理器返回 `{"detail": ...}`（前端 HTTP 层映射为 `{success, message}`，见 §5 通用节）。
**落地范围（过渡期约定）**：D 域新接口（scan/settings/stats/orders 列表）用 Envelope 包 `data`；
历史接口（auth/stations/charging/订单详情）保持原形状，避免一次性破坏前端。全局切换留待前端同步 PR（§9.4）。
C 域新增接口（estimate/vehicle）暂沿用裸形状（同历史接口），待全局切换一并收编。

### 5.7 vehicle（C 域 · Story 4）
| GET `/vehicle/current` | 200 `VehicleOut`（当前用户默认车辆；无记录时懒建一条默认值再返回） |

`VehicleOut = {plateNo, battery, rangeKm}`；默认 `{plateNo: "", battery: 75, rangeKm: 260}`。

### 5.8 B1 WebSocket 实时推送（二期 B 域）
| WS `/ws/charging/session/{session_id}` | 鉴权 `?token=` 或首帧 `{"token"}`；归属校验失败 404 语义；1s 推一帧 `RealtimeOut`（camelCase） |

帧格式：`RealtimeOut`（同 §5.3）；会话结束推送 `{"type":"session_finished","sessionId":...}` 后关闭（1000）；
未登录 4401、无进行中会话 4404。数据与 `GET /charging/current` 走同一 `RealtimeProvider`，两路口径一致；
HTTP 轮询端点保留作降级。

### 5.9 B2 独立模拟桩 REST（二期 B 域，设备侧协议）
| POST `/simulator/register` | `{deviceId, pileCode}` → `{simulatorId, pileStatus, heartbeatIntervalSec}`；桩不存在 404、已被占用 409 |
| POST `/simulator/{simulatorId}/heartbeat` | — → `SimulatorStateResponse`（桩权威状态随帧带回） |
| POST `/simulator/{simulatorId}/telemetry` | `{voltage, current, powerKw, energyKwh}` → 回执（遥测入 `SnapshotCache`） |
| POST `/simulator/{simulatorId}/done` | 设备停充上报 → 后端裁决结算（见 §7，`settle_active_order_for_pile`） |

—— 设备只上报计量数据，**桩状态与结算裁决权在 `services/charging.py`**（防割裂红线）；注册表/遥测进程内，
后端重启后模拟器重新注册即可。独立设备程序为 `scripts/charger_sim.py`（命令行运行，非 uvicorn 服务）。
`/simulator/*` 为设备链路，**不做用户鉴权**；生产部署需置于内网或加网关鉴权（本期属演示/联调用途）。

### 5.10 AI · 对话与车牌识别（feat/ai，v0.8）
| POST `/ai/chat` | `{messages:[{role,content}], maxTokens?, temperature?}` → 200 `Envelope<ChatData>`；503=未配置密钥/模型 |
| POST `/ai/plate` | `{imageDataUrl}`（`data:image/*;base64,...`）→ 200 `Envelope<PlateData>`；503/502 |

`ChatData={reply, model, usage?}`；`PlateData={plateNumber, confidence, rawText, model}`。密钥/模型走火山方舟 `ARK_*`（仅 `.env`）；系统提示与当前充电/最近订单上下文由后端注入（前端消息里自带的 system 会被覆盖去重）；接入说明见 `doc/AI接入使用说明.md`。

## 6. 鉴权与安全

- 密码 bcrypt 存储；JWT HS256，密钥走 `.env`（示例占位 `SECRET_KEY=change-me`，不提交）。
- CORS：开发期放开模拟器来源 origin，配置化。
- 所有订单/会话接口按 `user_id` 隔离，越权一律 404（不泄露存在性）。

## 7. 实时数据方案（分三期，统一经 `RealtimeProvider` 抽象取数）

前端只见 `GET /charging/current`，数据来源可切换、接口不变——这是防割裂的又一层：
`Settings.REALTIME_SOURCE = "sim" | "simulator" | "mqtt"`。

- **一期（当前实现）：服务端模拟（SimulatedProvider）**。移植前端 ChargeSimulator 公式：
  功率因子 `max(0.5, 0.8 − E/400)`，能量按 `dE/dt = P0·factor/3600` 积分——有解析解：
  `E(t) = 320 − (320 − E0)·e^(−P0·t/144000)`（E<120 段），此后按 0.5 倍额定线性；
  电压 `720 + 30·sin(t/7)`（确定性伪抖动，替代前端 Math.random，保证可测试）；
  电流 = 功率×1000/电压；费用 = 能量×订单单价快照。
  **按 `订单.start_time` 无状态推导**，服务重启不丢会话。前端 `ChargingPage` 由 setInterval 改为轮询本端点。
- **二期（已实现）：WebSocket `/ws/charging/session/{id}`（B1）与独立模拟桩 REST 遥测（B2）**。
  - B1 见 §5.8：按会话 1s 推一帧；HTTP 轮询端点保留作降级。
  - B2 见 §5.9：独立模拟桩进程把遥测经 `/simulator/{id}/telemetry` 写入 `SnapshotCache`；
    `REALTIME_SOURCE=simulator` 时 `SimulatorTelemetryProvider` 优先读遥测，无数据/陈旧回退 `SimulatedProvider`。
- **三期（预留位置）：MQTT 接入华为云 IoTDA，连接真实/模拟充电桩**。
  - `app/mqtt/`：`topics.py` 定义主题常量（`t/{pk}/charging/up` 状态上报、`.../cmd` 平台下行）；
    `consumer.py` 为接入桩：订阅桩上报 → 写入内存缓存 `{pile_id: RealtimeSnapshot}` →
    `MqttProvider` 供 `GET /charging/current` 读取（数据陈旧时回退模拟并告警）。
  - 依赖与配置预留但默认关闭：`.env` `MQTT_ENABLED=false`、`MQTT_HOST/PORT/ACCESS_TOKEN`（占位符，
    凭证严禁入库）；`aiomqtt` 依赖到三期再加，本期不引入。
  - 桩侧指令（远程启动/停止）同样走 `cmd` 主题；届时 `services/charging.py` 的不变式仍是唯一裁决处，
    MQTT 只做传输层，不改业务规则。

### 7.1 自动断电（Story 11，随 D 域实现）
后端在 `GET /charging/current`（前端轮询取数路径）内判断：若用户开启 `autoStop` 且当前电量
`energyKwh ≥ stopEnergyKwh`，则自动调用 `stop_order` 结算并返回 404（会话已结束），
与手动停止后的前端口径一致。触发与结算仍全部经 `services/charging.py`，不绕过不变式；
`stopThreshold`（电池百分比）需车辆电量来源（C 域 vehicle），后端仅留存偏好、暂不用于判定。

## 9. 契约同步与防割裂机制（重点）

1. **单一事实源**：本文档 §1.1 映射表 + §5 端点表。改任何字段/端点，先改文档、再改两端。
2. **契约快照测试**：`tests/test_contract.py` 断言每个响应模型的字段集合（camelCase 后）与
   本文档一致；前端 `Types.ets` 每个 interface 的字段清单同步写入该测试常量，**两端字段漂移即 CI 红**。
3. **OpenAPI 导出**：实现后 `python -m app.openapi_dump > doc/openapi.json` 提交仓库；
   前端以该文件为准生成/核对类型（IDE 里对照 `/docs`）。
4. **变更协议**：新增字段向后兼容（双方可先忽略）；删除/改名 = 破坏性变更，需版本号 `v2` 或双方同 PR 周期内落地；任何一端单方面改动视为 bug。
5. **联调日志**：`doc/联调记录.md`（实现阶段创建）按里程碑记录「已切换接口 / 遗留 mock / 差异问题」。
6. 本文档版本号随契约变更递增，前端 `缺项与待办记录.md` 第三节引用时注明所对版本。
